# RFC 0001: `createBus` — typed events across components, pages and tabs

Status: accepted design, not yet implemented · Package: `@sola-air-ui/core` · Touches: runtime, compiler (two macros), types

## Problem

A shell mounted beside a host app (a launcher, a command palette, an assistant
drawer, a toast stack) has to be told things by code it does not own: "the user
selected this record", "open the palette", "show this toast". It must also react
to the same signals when they come from another tab, and survive page loads.

Production use hand-rolled this as `solaBus.ts`: `CustomEvent` listeners,
`sessionStorage`, `BroadcastChannel` and role checks wired together per app.
Core now covers the state half (`createPersistentSignal`, `mountShell`,
`clearPersistentState`). The **event** half is still bespoke.

## Why not reuse what exists

| Need | Existing piece | Why it is not enough |
| --- | --- | --- |
| Shared *state* in one page | `signalMesh` / `createTopicSignal` | Last-value semantics: a write equal to the current value is dropped. Firing "ask Scout" twice with the same context must deliver twice. |
| State that survives pages and syncs tabs | `createPersistentSignal` | Same last-value semantics, and it stores. An event is not state; most should not be stored or replayed. |
| Ask an LLM | `$intent` | A different thing entirely. It stays exactly as it is. |

So events get their own primitive. **`$intent` is not overloaded.**

## API

```ts
import { createBus, bus } from '@sola-air-ui/core';

type Events = {
  'sola:context':  { title: string; data?: Record<string, unknown> };
  'sola:action':   { id: string };
  'sola:toast':    { kind: 'info' | 'error'; text: string };
  'sola:navigate': { view: string };
};

const b = createBus<Events>({
  channel: 'sola-bus',                         // BroadcastChannel name
  broadcast: ['sola:toast'],                   // types mirrored to other tabs (default: none)
  dom: {
    target: window,
    in:  ['sola:context', 'sola:action'],      // host page CustomEvents → bus
    out: ['sola:navigate'],                    // bus → CustomEvents on target
  },
  sticky: {
    'sola:context': { store: 'session', ttlMs: 30_000, consume: true },  // consume is required for 'session'
  },
  onReject: (info) => { /* in-page only; see "Rejections" */ },
  validate: {
    'sola:context': (p) => typeof p?.title === 'string',
    'sola:toast':   (p) => typeof p?.text === 'string',
  },
  guard: (e) => e.type !== 'sola:action' || canTriage(),   // app policy lives here
});

const off = b.on('sola:context', (payload, meta) => { /* ... */ });
b.emit('sola:toast', { kind: 'info', text: 'Saved' });
const ctx = b.signal('sola:context');          // reactive accessor of the latest payload
b.dispose();
```

- `emit(type, payload)`: validates, guards (`direction: 'out'`), delivers to local
  handlers, then mirrors to other contexts if the type is in `broadcast`, and
  re-dispatches to the DOM if the type is in `dom.out`.
- `on(type, handler)`: returns an unsubscribe. Handler receives `(payload, meta)`
  where `meta = { type, from: 'local' | 'dom' | 'remote', id, time, replayed }`.
- `signal(type)`: an `Accessor` over the latest payload, so events can drive
  `$derived`/`$effect` and the template. Unlike `signalMesh`, a repeated identical
  payload still updates it (each event is a new wrapper), so effects re-run.
- Package-level default instance `bus` for apps that need only one.

### Guards and validation (security boundary)

Anything on the page can dispatch a `CustomEvent`, and a `BroadcastChannel`
accepts any same-origin context. In a host page shared with many third-party
scripts, **every event that crosses a boundary is untrusted input**.

**Decision: secure by default at the boundaries, no ceremony inside the page.**

- A type listed in `dom.in` or `broadcast` **must** have a `validate` entry or be
  covered by `guard`. Declaring one without either is an error at `createBus()`
  time, not a silent hole. To accept a type deliberately unchecked, write it down
  (`validate: { 'x': () => true }`), so the decision is visible in review.
- Inbound events that arrive from `dom` or `remote` run `validate[type]` and then
  `guard({ type, payload, from, direction })`. Core ships **no** role logic; role
  gates such as "can triage" are supplied by the app.
- Same-page `bus.emit()` of a type that is **not** exposed to a boundary needs no
  validator unless the developer registers one. Internal component-to-component
  events pay nothing.
- A rejected event is dropped and reported through `onReject` (default: one
  `console.warn` per type in development), never thrown into the emitter.

### Rejections stay in-page

`onReject(info)` is a plain in-memory callback. It is **never** routed onto `dom.out`
or `bus.emit`.

- `info = { type, reason: 'invalid' | 'guard' | 'unlisted', from, direction }`.
  It deliberately **does not include the payload**: a rejected event often failed
  because it was malformed or unauthorised, and the raw data should not be
  forwarded by accident.
- Why not forward through the DOM bridge: a script spamming invalid events would
  turn each one into an outbound `CustomEvent`, an amplification loop if any host
  listener reacts by dispatching again; and rejection details would be readable by
  every script on the page.
- The app decides what to do inside the callback: log to its own telemetry with its
  own rate limit, or call `window.dispatchEvent` with a sanitised summary. The default
  (no `onReject`) is one development-mode `console.warn` per type, without the payload.

### Delivery semantics

- At-most-once, no ordering guarantee across tabs, no replay except `sticky`.
- **Local by default.** Only types listed in `broadcast` leave the page. A consequential
  action (`sola:action`) must not fire in every open tab as a side effect of one click
  (for example, duplicate LLM calls in every tab).
- Echo/loop safe: each context stamps its id; remote events are not re-broadcast.

### Sticky events (v1)

Host widgets and shells mount asynchronously, so an event emitted a moment before a
shell attaches its handler (or just before a page navigation) would otherwise be lost.

```ts
sticky: { 'sola:context': { store: 'memory' | 'session', ttlMs: 30_000, consume: false } }
```

- `store: 'memory'` replays the last payload to handlers registered later **in the
  same page**. `store: 'session'` also survives a navigation in that tab (same
  storage layer, versioning and `ttlMs` as `createPersistentSignal`).
- `ttlMs` is **required** and short. An event from twenty minutes ago never replays on a
  fresh load.
- `consume` is **required whenever `store: 'session'`** (construction error otherwise;
  it does not apply to `memory`). Forcing the choice matters because the two uses
  are opposites:
  - `consume: true`, a one-shot handoff ("open this in the drawer after navigating"):
    a reload must not repeat it.
  - `consume: false`, ambient context that several islands read ("the selected
    incident", read by both the drawer and the palette): it must stay available.
- Replays carry `meta.replayed = true` and are delivered to each late handler once.
- **What `consume: true` does:** it applies to *storage*, not to the page. The first time
  any handler receives the replay, the stored copy is deleted, so a reload or a new
  navigation cannot replay it. The in-memory copy stays until `ttlMs`, so a sibling
  island that mounts a moment later in the same page (a different tick, so a
  microtask-boundary purge would not be reliable) still receives it. First-mounted
  island therefore never starves the others.
- **Do not make consequential actions sticky.** A replayed `sola:action` could repeat
  work (for example, another LLM call after a reload). Core cannot tell which types are
  consequential, so this is guidance, backed by `meta.replayed` so a handler can ignore
  replays, and by `consume` for one-shot handoffs.
- `clearPersistentState()` also wipes sticky events (sign-out).

### DOM bridge (two-way, explicit allowlists)

`dom.in` forwards host `CustomEvent`s into the bus (`from: 'dom'`, so validation and
guards apply). Host apps need no import of Sola at all:

```js
window.dispatchEvent(new CustomEvent('sola:context', { detail: { title: 'INC0012' } }));
```

`dom.out` re-dispatches listed bus events as `CustomEvent`s on `target`, so a command
palette or an action chip can tell the host to change view or filter a table
without the component importing the host's router, and so hosts can log
`sola:action` for telemetry.

- **Both directions are allowlists.** Nothing is bridged by default. Internal bus
  traffic never leaks onto `window`, where any host script can read it.
- Anything in `dom.out` is readable by every script on the page. Never put sensitive
  data in an outbound payload; the allowlist makes that surface auditable.
- A type may not appear in both `in` and `out` (construction error), and re-dispatched
  events are tagged so the bridge never re-ingests its own output.

## Compiler surface (two macros, `$intent` untouched)

```html
<script>
  $on('sola:context', (ctx) => { title = ctx.title; });   // subscribes, auto-unsubscribes on destroy
  let last = $lastEvent('sola:context');                   // reactive accessor of the latest payload
</script>
<p>{last()?.title}</p>
```

- `$on(type, fn)` → `bus.on(type, fn)` plus `onDestroy` cleanup.
- `let x = $lastEvent(type)` → `const x = bus.signal(type)`, read like `$state`.
  Named `$lastEvent`, not `$event`: `$event` already means "the DOM event object" in
  Angular, Vue and Alpine templates, and `x` here is last-value state, not a discrete
  event. `$on` runs on every emission (duplicates included); `$lastEvent` is state
  for markup.
- Both use the default `bus` unless the file imports another instance as `bus`.

## Non-goals

- No request/response RPC, no delivery guarantees, no leader election.
- No cross-origin messaging (`postMessage` between origins is a separate concern).
- No role or permission model in core.

## Migration of a hand-written `solaBus.ts`

State parts (session persistence, cross-tab sync, theme) already map to
`createPersistentSignal`. The event parts map to `createBus`: listeners become
`b.on`, `dispatchEvent` calls stay as they are via the DOM bridge, and the role
checks become the `guard` callback.

## Test plan

Unit (node): emit/on/off, repeated identical payload delivers twice, validation
and guard reject paths, `broadcast` list respected, no echo, sticky replay and
TTL, `clearPersistentState` clears sticky, dispose releases channels (the
`afterEach` leak pattern from `persist.test.js`).
Compiler: `$on` cleanup wiring, `$lastEvent` read rewrite.
Browser: two pages, DOM `CustomEvent` → shell in a closed shadow root, cross-tab toast.

## Decisions

1. **Strict mode**: on by default **at the boundaries** (`dom.in`, `broadcast`), off for
   same-page emits. There is no global flag.
2. **Sticky**: ships in v1, with a required short `ttlMs`, `memory` | `session` stores,
   a required explicit `consume` for `session`, and `meta.replayed`.
3. **`consume` semantics**: purges *storage* on first replay; the in-memory copy lives to
   `ttlMs` so sibling islands mounting later in the same page are not starved.
4. **DOM bridge**: two-way, with explicit `in` and `out` allowlists, disjoint.
5. **Rejections**: in-page callback only, payload-free, never on `dom.out` or the bus.
6. **Macros**: `$on(type, fn)` and `$lastEvent(type)`.
